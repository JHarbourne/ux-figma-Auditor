# ADR-001: Figma Make to GitHub Experiment

## Status
Draft

## Context
This is an experiment to understand how code generated from Figma Make can be moved into GitHub and later into Azure DevOps for production use.

The goal is to:
- explore the quality of generated code
- understand how repositories are created and managed
- test basic governance approaches (ADR, documentation, CI/CD)
- identify gaps between prototype code and production-ready applications

The application is a simple internal tool prototype (UX / Accessibility use case).

## Decision
We will:
- Use Figma Make to generate initial application code
- Push the generated code into a GitHub repository
- Add basic documentation and governance (ADR, README)
- Experiment with simple CI/CD using GitHub Actions
- Optionally connect or migrate the repository into Azure DevOps

## Rationale
This approach allows:
- rapid prototyping and experimentation
- hands-on understanding of code quality and structure
- validation of a UX-to-production workflow
- exploration of how AI-generated code fits within enterprise governance

GitHub is used as the initial platform because:
- it integrates directly with Figma Make
- it is easy to use for experimentation
- it supports lightweight CI/CD

## Alternatives considered
### Option 1: Do nothing (stay in Figma only)
- Rejected because no real understanding of production workflow would be gained

### Option 2: Start directly in Azure DevOps
- Rejected because it introduces unnecessary complexity for early experimentation

### Option 3: Use Power Platform instead
- Not selected for this experiment, as the goal is to understand generated code workflows

## Data and security considerations
- No real or sensitive data will be used
- All data is dummy/test data
- Repository is private
- No external integrations

## UX and accessibility requirements
- Basic usability should be maintained
- Future versions should aim for WCAG 2.2 AA compliance
- Accessibility considerations will be reviewed during later stages

## Consequences
### Positive
- Hands-on understanding of design-to-code workflows
- Improved ability to define governance processes
- Better insight into limitations of AI-generated code

### Negative
- Code quality may be poor or inconsistent
- Additional effort required to structure and improve code
- Not suitable for production without further engineering work

## Risks
- Generated code may be difficult to maintain
- Lack of clear architecture
- Over-reliance on AI without sufficient validation

## Ownership
- Experiment owner: UX (Jonathan Harbourne)
- Future ownership for production use: to be defined

## Next steps
- Push code from Figma Make into this repository
- Review and refactor code using Copilot or similar tools
- Add basic CI pipeline
- Evaluate potential migration to Azure DevOps
